      Marker syntaxSintaxis de marcadorSintassi del marcatore

      Everything lives inside <!-- --> HTML comments, so none of it renders on GitHub. There are exactly two kinds of marker.Todo vive dentro de comentarios HTML <!-- -->, así que nada de esto se renderiza en GitHub. Hay exactamente dos tipos de marcador.Tutto vive all'interno di commenti HTML <!-- -->, quindi nulla di questo viene renderizzato su GitHub. Esistono esattamente due tipi di marcatore.

      Declaring a tableDeclarar una tablaDichiarare una tabella

      <!--[[ name ]]-->
key = "value"
another_key = "another value"
<!--/-->
      • name must be a bare identifier ([A-Za-z_][A-Za-z0-9_]*) — no dots, no sigils. Any name works; nothing is reserved.name debe ser un identificador simple ([A-Za-z_][A-Za-z0-9_]*) — sin puntos, sin sigilos. Cualquier nombre funciona; ninguno está reservado.name deve essere un identificatore semplice ([A-Za-z_][A-Za-z0-9_]*) — senza punti, senza sigilli. Qualsiasi nome funziona; nessuno è riservato.
      • The body is a small TOML subset: one key = "value" pair per line, double quotes only, no escapes, no arrays, no nested tables, no numbers/booleans/dates as distinct types — everything is a string. Blank lines and # comments are ignored.El cuerpo es un pequeño subconjunto de TOML: un par key = "value" por línea, solo comillas dobles, sin escapes, sin arreglos, sin tablas anidadas, sin números/booleanos/fechas como tipos distintos — todo es una cadena de texto. Las líneas en blanco y los comentarios # se ignoran.Il corpo è un piccolo sottoinsieme di TOML: una coppia key = "value" per riga, solo virgolette doppie, nessun escape, nessun array, nessuna tabella annidata, nessun numero/booleano/data come tipo distinto — tutto è una stringa. Le righe vuote e i commenti # vengono ignorati.
      • Declaring the same table name twice is a hard error.Declarar el mismo nombre de tabla dos veces es un error fatal.Dichiarare due volte lo stesso nome di tabella è un errore fatale.
      • A table with no closing <!--/--> is a hard error — table bodies are hand-written, never auto-generated, so there's nothing to insert for you.Una tabla sin <!--/--> de cierre es un error fatal — los cuerpos de tabla se escriben a mano, nunca se generan automáticamente, así que no hay nada que insertar por ti.Una tabella senza <!--/--> di chiusura è un errore fatale — i corpi delle tabelle sono scritti a mano, mai generati automaticamente, quindi non c'è nulla da inserire per te.

      Referencing a valueReferenciar un valorFare riferimento a un valore

      <!--[[ $table.key ]]-->
...generated content...
<!--/-->
      • $table.key inserts that key's value as literal text.$table.key inserta el valor de esa clave como texto literal.$table.key inserisce il valore di quella chiave come testo letterale.
      • @table.key's value is instead treated as a path, read from disk (relative to the working directory sigilmd was run from), and its file contents are inserted. Missing file → hard error.El valor de @table.key se trata en cambio como una ruta, se lee del disco (relativa al directorio de trabajo desde el que se ejecutó sigilmd), y se inserta el contenido de ese archivo. Archivo faltante → error fatal.Il valore di @table.key viene invece trattato come un percorso, letto dal disco (relativo alla directory di lavoro da cui è stato eseguito sigilmd), e il contenuto di quel file viene inserito. File mancante → errore fatale.
      • References can be chained by concatenation, with no separator: <!--[[ @$file.dir$intro.name ]]--> resolves $file.dir and $intro.name, concatenates them, and since the marker starts with @, reads the resulting path as a file. $a.b$c.d (no leading @) does the same concatenation but inserts the result as literal text instead.Las referencias pueden encadenarse por concatenación, sin separador: <!--[[ @$file.dir$intro.name ]]--> resuelve $file.dir y $intro.name, los concatena, y como el marcador comienza con @, lee la ruta resultante como un archivo. $a.b$c.d (sin @ al inicio) hace la misma concatenación pero inserta el resultado como texto literal en su lugar.I riferimenti possono essere concatenati per concatenazione, senza separatore: <!--[[ @$file.dir$intro.name ]]--> risolve $file.dir e $intro.name, li concatena, e poiché il marcatore inizia con @, legge il percorso risultante come un file. $a.b$c.d (senza @ iniziale) esegue la stessa concatenazione ma inserisce il risultato come testo letterale.
      • A reference to a table or key that doesn't exist is a hard error. A bare name with a . in it but no leading $ (a dropped sigil, the most likely typo) is also a hard error, with a hint at the fix.Una referencia a una tabla o clave que no existe es un error fatal. Un nombre simple con un . pero sin $ al inicio (un sigilo omitido, el error tipográfico más probable) también es un error fatal, con una sugerencia para corregirlo.Un riferimento a una tabella o chiave inesistente è un errore fatale. Un nome semplice con un . ma senza $ iniziale (un sigillo omesso, l'errore di battitura più probabile) è anch'esso un errore fatale, con un suggerimento per la correzione.
      • On first run, the closing <!--/--> doesn't need to exist yet — sigilmd writes it for you. On every later run, it replaces only what's between the two markers, leaving both markers themselves untouched.En la primera ejecución, el <!--/--> de cierre no necesita existir todavía — sigilmd lo escribe por ti. En cada ejecución posterior, reemplaza solo lo que hay entre los dos marcadores, dejando ambos marcadores intactos.Alla prima esecuzione, il <!--/--> di chiusura non deve ancora esistere — sigilmd lo scrive per te. In ogni esecuzione successiva, sostituisce solo ciò che sta tra i due marcatori, lasciando intatti entrambi i marcatori.
      • If a reference marker has other text before it on the same source line, the generated content is inserted inline, on that same line. If the marker sits alone on its own line, generated content is inserted as its own block.Si un marcador de referencia tiene otro texto antes en la misma línea de origen, el contenido generado se inserta en línea, en esa misma línea. Si el marcador está solo en su propia línea, el contenido generado se inserta como su propio bloque.Se un marcatore di riferimento ha altro testo prima di esso sulla stessa riga sorgente, il contenuto generato viene inserito in linea, su quella stessa riga. Se il marcatore è da solo sulla propria riga, il contenuto generato viene inserito come blocco a sé stante.

      What is not supported, on purposeLo que no es compatible, a propósitoCosa non è supportato, di proposito

      No conditionals, no loops, no arithmetic, no function calls, no string concatenation inside the TOML values themselves. Chaining lives only in the reference markers, and only as juxtaposition of $table.key lookups — never as a general expression language. Every rule above is meant to be complete, not a starting point.Sin condicionales, sin bucles, sin aritmética, sin llamadas a funciones, sin concatenación de cadenas dentro de los propios valores TOML. El encadenamiento existe solo en los marcadores de referencia, y solo como yuxtaposición de búsquedas $table.key — nunca como un lenguaje de expresiones general. Cada regla anterior está pensada para ser completa, no un punto de partida.Nessun condizionale, nessun ciclo, nessuna aritmetica, nessuna chiamata di funzione, nessuna concatenazione di stringhe all'interno dei valori TOML stessi. La concatenazione esiste solo nei marcatori di riferimento, e solo come giustapposizione di ricerche $table.key — mai come un linguaggio di espressioni generale. Ogni regola sopra è pensata per essere completa, non un punto di partenza.

      Real markers have no space after <!-- or before -->. The scanner matches <!--[[...]]--> anywhere in the file, including inside fenced code blocks — it has no notion of Markdown fences or of any other tool's marker syntax, and hard-errors on anything it doesn't recognize.Los marcadores reales no tienen espacio después de <!-- ni antes de -->. El escáner busca <!--[[...]]--> en cualquier parte del archivo, incluso dentro de bloques de código cercados — no tiene noción de los fences de Markdown ni de la sintaxis de marcador de ninguna otra herramienta, y genera un error fatal ante cualquier cosa que no reconoce.I marcatori reali non hanno spazio dopo <!-- o prima di -->. Lo scanner cerca <!--[[...]]--> in qualsiasi punto del file, anche all'interno di blocchi di codice recintati — non ha alcuna nozione dei fence di Markdown né della sintassi di marcatore di nessun altro strumento, e genera un errore fatale su qualsiasi cosa non riconosca.

      External configConfiguración externaConfigurazione esterna

      Table declarations can also live in a separate TOML file instead of (or in addition to) inline <!--[[ name ]]--> blocks, using real TOML syntax:Las declaraciones de tabla también pueden vivir en un archivo TOML separado en lugar de (o además de) bloques <!--[[ name ]]--> en línea, usando sintaxis TOML real:Le dichiarazioni di tabella possono anche vivere in un file TOML separato invece di (o in aggiunta a) blocchi <!--[[ name ]]--> in linea, usando la sintassi TOML reale:

      [intro]
file = "assets/intro.md"

[version]
value = "1.4.2"

      Pass its path via the config input. A table name declared in both the target file and the external config is a hard error.Pasa su ruta mediante la entrada config. Un nombre de tabla declarado tanto en el archivo destino como en la configuración externa es un error fatal.Passa il suo percorso tramite l'input config. Un nome di tabella dichiarato sia nel file di destinazione sia nella configurazione esterna è un errore fatale.

      CICICI

      The workflow in .github/workflows/ci.yml runs the test suite across a matrix of Perl releases (native runner + older interpreters back to 5.8), a composite-action end-to-end run against a scratch fixture, and two dogfooding jobs that verify the README's borrowed content — the project-structure tree (via treegen2) and the badges (via sigilbadges) — is current.El workflow en .github/workflows/ci.yml ejecuta la suite de pruebas en una matriz de versiones de Perl (runner nativo + intérpretes más antiguos hasta 5.8), una ejecución de extremo a extremo de la acción compuesta contra un fixture temporal, y dos jobs de dogfooding que verifican que el contenido tomado por el README — el árbol de estructura del proyecto (vía treegen2) y los badges (vía sigilbadges) — esté actualizado.Il workflow in .github/workflows/ci.yml esegue la suite di test su una matrice di versioni di Perl (runner nativo + interpreti più vecchi fino a 5.8), un'esecuzione end-to-end dell'azione composita contro un fixture temporaneo, e due job di dogfooding che verificano che il contenuto preso in prestito dal README — l'albero della struttura del progetto (via treegen2) e i badge (via sigilbadges) — sia aggiornato.
